# Bulletin public metrics

## TL;DR

- **What:** a public Grafana dashboard of liveness, bitswap and HOP metrics from external Bulletin collators.
- **Operators:** add one `/metrics` route to their existing reverse proxy, allowed only from our IP. No restart, no new port. See [OPERATORS.md](OPERATORS.md).
- **Us:** run `docker compose up -d` on a server with a public subdomain, then add each operator to `prometheus/targets/operators.yml`.
- **Status:** tested end to end on a local network (two collators, `stable2609`). Deployed on `51.159.191.39`. Waiting for the DevSecOps subdomain.

## Details

### How it works

Prometheus scrapes each operator's `/metrics` URL through the operator's own
reverse proxy. Grafana shows the data read-only to anyone.

```
operator host                              this server
collator :9615 (localhost) <- proxy <-- Prometheus -> Grafana -> Caddy (TLS) -> public
                         (allows only this server's IP)
```

### Files

- `docker-compose.yml`: Prometheus, Grafana, Caddy. The `local` profile adds
  two stand-in operator proxies (nginx and Caddy) for testing.
- `prometheus/prometheus.yml`: the scrape job. Keeps `substrate_rpc_calls_*`
  only for the HOP methods (see the comment there).
- `prometheus/targets/operators.yml`: one entry per operator. Prometheus
  reloads it on change.
- `grafana/dashboards/bulletin-collators.json`: the dashboard, generated by
  `tools/build-dashboard.py` from the internal Paseo dashboard in
  `paritytech/bulletin-grafana-dashboards`.
- `OPERATORS.md`: instructions for operators.
- `local/`: a local network with two collators and their scrape targets for
  testing.

### Run on the server

Requirements: a VM with a static public IP, Docker with the compose plugin,
DNS for the subdomain pointing to the VM, ports 80 and 443 open.

```sh
cat > .env <<EOF
GRAFANA_ADMIN_PASSWORD=<random>
PUBLIC_DOMAIN=<subdomain>
GRAFANA_ROOT_URL=https://<subdomain>/
PUBLIC_HTTP_PORT=80
PUBLIC_HTTPS_PORT=443
EOF
docker compose up -d
```

Before the subdomain exists, set `PUBLIC_DOMAIN=:80` and
`GRAFANA_ROOT_URL=http://<ip>/` to serve plain HTTP on the IP.

### Add an operator

Append to `prometheus/targets/operators.yml`:

```yaml
- targets: [bulletin.example.org]
  labels:
    operator: example
    __scheme__: https
    __metrics_path__: /metrics
```

Check: Prometheus → Status → Targets shows the operator as `UP`.

### Test locally

1. `local/run-network.sh`: starts a relay chain and two Bulletin collators
   (polkadot-sdk `stable2609`) with metrics on `localhost:9615` and `:9715`.
2. Create `.env` with `GRAFANA_ADMIN_PASSWORD=<anything>`. If Docker runs in a
   VM (Lima, Colima), also set `HOST_GATEWAY` to the host's address as seen
   from the VM (Lima: `192.168.5.2`).
3. `cp local/targets.yml prometheus/targets/local.yml` (git ignores this copy).
4. `docker compose --profile local up -d`
5. Open `http://localhost:8080`.

The dashboard needs traffic to show bitswap and HOP data; the
`examples/hop_round_trip.js` and `examples/authorize_and_store_papi.js`
scripts in `polkadot-bulletin-chain` generate it.

### Rebuild the dashboard

```sh
tools/build-dashboard.py <path>/bulletin-paseo-dashboard.json > grafana/dashboards/bulletin-collators.json
```
